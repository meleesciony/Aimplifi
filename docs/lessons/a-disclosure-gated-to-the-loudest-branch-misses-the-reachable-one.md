# A disclosure gated to the loudest branch misses the reachable one

**One line:** the branch where a defect is most dramatic (the all-zero, the total wipeout) is
usually its LEAST reachable shape — gate a disclosure there and the common, partial shape ships
silent; and if the companion surface (a trace, a drawer) only renders for stated figures, the
zero-gated mirror is dead code that narrates a screen the app never draws.

**Where it was paid for (U.19–U.22 critic cycle, DECISIONS #456, 2026-08-12).** U.21's task row
was written from its most vivid symptom: a doubled released return empties a category, every
category drops, and Ask prints "No spending recorded" — an affirmative falsehood. The slice
dutifully covered the ZERO branches and stopped. The money critic executed the miss in one
fixture: one surviving category plus one dropped category rendered "You spent $50.00 on
Food & Dining this month." — a positive, UNDERSTATED figure with no note anywhere, while the
engine's own record held the dropped rows. A doubling that only partially cancels a breakdown
is strictly more reachable than one that empties it, and understatement is the failure
direction that costs money.

The same gating produced a second, quieter defect: the trace mirror was gated on the zero
conditions too, but a trace only attaches where an answer STATES a figure (`headlineCents`),
and zero branches state none — so the mirror was dead code, its docstring describing a drawer
under "No spending recorded" that the app never renders. Ungating the note (self-gated on the
fact, not the figure's sign) fixed the reachable miss AND made the mirror real in one move.

**The rule:** when adding a disclosure, derive its gate from the FACT being disclosed (the
dropped set is non-empty), never from the branch where the defect was first noticed (the figure
is zero). Then walk every companion surface and check the gate against that surface's own
reachability — a condition copied from the answer can be dead on the trace.
