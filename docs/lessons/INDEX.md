# Lessons index

Cross-session memory. One line per lesson: `- [title](file.md) — one-line hook`.
Convention lives in `LOOP_ENGINEERING.md` → "Lessons ledger": one lesson per file, one-line summary at
the top, corrections and confirmed approaches alike with the *why*, no duplicates of what the repo or
ledgers already record, update rather than duplicate, delete lessons proven wrong.

- [Don't develop in cloud-synced folders](cloud-synced-folders.md) — OneDrive file locks cause spurious verify failures and CRLF churn; one-off cold-start failures that don't reproduce are environment flakes.
- [Generate code with Write/Edit, not shell heredocs](windows-codegen-via-shell.md) — bash→python heredocs mangled 
 escapes in generated TS and `*/` inside comments broke builds; file tools are byte-exact.
- [Diagnose hangs at boundaries, not by correlation](diagnose-hangs-at-boundaries.md) — load-correlated evidence pattern-matched the triage stall to the SQLite flake twice; paired client/server probes acquitted it in one run (React lane entanglement was the cause), and fixing the chronic failure unmasked two ordering bugs hidden behind it.
- [Mutation forms use onSubmit, never useActionState](mutation-form-recipe.md) — React 19's form-action auto-reset silently reverts uncontrolled `<select>`s to their first option on the error return → a silent mis-file; the proven recipe is onSubmit + own busy + withDeadline + reload/navigate on success. Bit #166 and again #170. **Extended #216:** the same principle in reverse — a CONTROLLED input loses text typed before hydration (state never sees it, render blanks the box, submit pushes the unfiltered URL and the query vanishes silently); let the DOM own typed text and read it via FormData at submit.
- [mobile-380 Playwright viewport-scaling flake](mobile-380-viewport-scaling-flake.md) — a ~11.8% viewport scaling mismatch could make fixed-bottom-nav clicks intercept. **CORRECTED #193:** the recurring "full e2e can't exit 0 here" was actually a DETERMINISTIC auth.spec strict-mode locator bug (#182's "Sign out of all devices"), not this flake, which did not reproduce across 3 full runs post-#187/PW-1.60; full e2e now exits 0. Read the error signature before blaming the flake — `intercepts pointer events` is it, anything else is a real bug.
- [CI (GitHub Actions Linux runner) e2e timing flake](ci-e2e-timing-flake.md) — a different `toHaveCount`/timeout assertion fails each rerun of the same unchanged commit (budget-targets, then phase2-triage), while unit tests and the untouched code stay green; runner resource contention, not a regression — distinct from the mobile-380 flake (different environment, different error signature).
- [The local full-suite e2e flake is load-induced, and its symptom varies by page](e2e-dials-value-corruption-flake.md) — a *corrupted persisted value* (`ClimbingTravel`) looked like a real data-integrity bug until a full verify on **clean HEAD** failed too, on a different test (a 60s click timeout). One cause (fill lands mid-hydration under contention), two symptoms. The settling move is a stashed clean-tree gate run — do that BEFORE writing the diagnosis; serialize the gate, and let CI arbitrate e2e.
- [Second-person copy is a load-bearing invariant, not a style choice](second-person-copy-scope.md) — `reminderLine`'s "you'll pay $600 yourself" was true only because it had always rendered the reader's OWN card; the joint household digest fed it a PARTNER's card and it became a false money claim that invited a double payment. When a surface widens whose data flows into an existing copy string, re-read every sentence for its implied subject. **Extended #221:** fixing one surface is not fixing the bug — the identical disease survived on the reminders card, /cards, and the headline until the slice-8 critic swept the DATA CLASS; when a copy-subject bug is found anywhere, grep every other surface fed by the same widened data before closing it.
- [Widening a single-actor field to multi-actor requires re-auditing every consumer](multi-actor-field-scoping.md) — `Correction.userId` went from "always the owner" to "the acting user" (household slice 6, partner categorization); a fresh-context critic caught a DIFFERENT pre-existing consumer (Plaid's pending→posted id-churn transplant) still filtering by the old owner-only assumption, silently stranding and reverting a partner's fix — grep every consumer of a widened column, not just the write path being changed.
- [The demo account is one shared row — anything that learns from a user's INPUT must fence it off](shared-demo-account-must-not-learn.md) — every anonymous visitor is the same `user-demo`, so a feature that stores what a user typed and shows it back leaks one stranger's words to the next (household #210, learned vocabulary #226); PII-scrubbing is not anonymization, and a constant both auth and a cron need belongs in a leaf module.
- [A guard must read the same input as the thing it guards](a-guard-must-read-what-it-guards.md) — the fix for "spend at 星巴克 → the all-spending total" tested the first token while the tokenizer skipped leading articles, so the identical bug survived one article away ("at **the** 星巴克"); share the token stream instead of re-parsing, and always write the false-abstain test (the same guard had started refusing "mcdonald’s", the iOS default apostrophe). **Extended #229 (the 2.6 inversion):** the positive licence failed the same way one level down — one consumed FIRST token licensed the whole object ("at **Best** Buy" took the total), and the carve-out's PREFIX equality was containment in disguise ("at café in 星巴克 town"); a licence must consume the ENTIRE unit it licenses.
- [A self-improving loop leaks in its BACK half](self-improving-loops-leak-in-the-back-half.md) — the abstention gates survived three critics; every P1 was in the half nobody watches: an undo a background job can overwrite, a rule nothing checks once it starts answering (excluding your own output from your own evidence creates the blackout — replace the signal you removed), and a "held-out" boundary drawn from a wall clock.
- [A precision fix that fabricates $0 is worse than a safe category-superset](precision-fix-that-fabricates-is-worse-than-a-safe-superset.md) — TASKS 2.8 tried to route "at travel lodge"/"at 24 hour fitness" to the merchant instead of the category superset; three Fable critic cycles proved "SHELL gas station" (brand) and "FANCY gas station" (adjective) are inseparable without a merchant DB, and the fix regressed common category questions ("at gas stations") into confident $0 fabrications — reverted; the deliverable is the finding (merchant-DB-blocked), not the code. Check a fix's failure DIRECTION, not just its precision.
- [Copying a value verbatim is not copying its meaning](verbatim-value-not-verbatim-meaning.md) — the nudge feed's `centsAtStake` is carried byte-for-byte but MEANS a different thing per kind (the monthly INCREASE for price-increase, an ESTIMATED saving for insurance/negotiable, the user-action REMAINDER after autopay for payment_due); the verbatim-copy rule guarantees the number, never that one display template describes it honestly — the false-money-copy risk (#221 class) moves to the UI boundary, bit twice in slice-2 critic cycles (opportunity kinds, then partial-autopay remainder-as-total). Label each case at the boundary, disclose estimates inline, carry sibling context (autopayCents) to show splits without summing, and lock with a rendered-copy test.
- [A fence copied per call site will miss call sites](fence-by-construction-not-per-call-site.md) — #242's demo fence missed 2 of 5 LLM call sites the same session had just edited; make the guarded capability obtainable ONLY through a fencing constructor (`categorizeSuggestFor`) so the invariant holds by construction and one executed test covers every site, including future ones.
- [Context-carrying features are judged by what they ABSTAIN on](context-carrying-features-must-abstain.md) — the Ask conversation frame passed 29 happy-path tests and was still wrong three ways: every bug was a fragment it shouldn't have resolved (a dropped merchant, an ignored negation, the assistant's own vocabulary read as a store). Write the abstention tests first and make them the majority; enumerate the input classes the feature cannot represent (negation, comparison, causation, advice) and bail out on each; test both extraction orders; re-derive anything carried across time; and re-read a validator the moment its field starts crossing a client boundary. **Extended #230:** when declaring an abstention invariant for "every route", enumerate routes from the answer surface backward (parser, intentFromKind, vocab, AND the frame) — the frame was forgotten a third time and silently dropped an unresolvable date, answering the carried window.
