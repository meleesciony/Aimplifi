# A resolution rule that resolves on conflict will eventually resolve wrong — and a guess may not be offered where a proof is withheld

One line: two correct stages composed without a shared invariant produce a wrong answer between
them; and evidence systems need ONE rule at every level — conflicting evidence is an absence —
plus ONE precedence — the system's own proof always outranks a guess.

From TASKS L.9 (2026-07-26), four critic cycles over the duplicate-detector's retirement veto and
ambiguity carry-out. The owner case: one stale Roth IRA offered against BOTH a Roth and a
Traditional at the same badge.

**Conflicting evidence is an absence — at EVERY level, not the first one you think of.** The
veto resolved "roth" from any name token. Three critics each found a level where resolution-on-
conflict was still happening: within a name ("Jill Roth - Traditional IRA" — bank-composed names
embed the HOLDER'S name, and Roth is a common surname), between name and subtype ("Roth IRA" +
subtype `traditional` → resolved pretax and vetoed a REAL Roth pair), and between evidence and
absence (bare `ira` is Plaid's specialised value AND its unspecialised fallback, so it can
license nothing). Each pass fixed one level while the doctrine claimed the class was closed —
the same shape as `a-disclosure-is-several-claims-in-one-sentence.md`. The rule that finally
held: each source resolves alone, any disagreement between or within sources is NULL, and an
absence is never a difference. Record the IRREDUCIBLE window too ("Jill Roth - IRA" is token-
identical to a real Roth IRA — no rule keeps both), or the next session rediscovers it as a bug.

**A guess may not be OFFERED where a proof is withheld (stage composition is a test surface).**
The withhold guard (a stale row with two live proven choices offers neither) and the grouping
stage (one predecessor, several matches → ambiguity) were each correct and each locked — and
never tested together. A stale row whose proven folds were withheld reached grouping with only
its heuristic matches, and a lone name-match surfaced as a clean sole candidate: a fold the app
could PROVE was the wrong account, one tap away. The fix was not in either stage but in their
contract: `withheldProvenPredecessors` crosses the boundary. When a change has a withhold stage
AND an offer/group stage, write the test that feeds a withheld item into the second stage, or a
critic will.

**Count guards by ROLE, not by pair.** A liveness-blind "proven partner count" deadlocked a real
fold twice over: a DEAD partner can never compete for a fold (no direction), and a BOTH-LIVE
tangle belongs to the combine card. The counting that worked: directed pairs count only against
their dead side (competing successor choices), both-live pairs count each live side (unresolved
combine), both-dead counts nothing — all computed AFTER the caller's exclusion, so resolving a
pair releases what it guarded (a guard must read what it guards, extended: it must also count
only what can compete).

**A critic finding executed before fixing is worth four cycles; the cap exists because each fix
births the next layer.** Every cycle's P1 was reproduced by the critic's own throwaway suite
before it entered a fix, and every cycle's fix was the previous cycle's untouched interaction
surface (counting → suppression → carry-out completeness). The 4-cycle cap then stopped the
descent at an advisory-direction silence (a proven ambiguity carried out nowhere — pre-existing,
no wrong action offered), which was the right thing to RECORD with a fix sketch rather than to
fix uncriticized — a fifth fix's failure modes were already visible (its how-to would name
remedies and controls, the exact class three of the four cycles found P1s in).
