## #737 - Goal progress + pace: how far along, and does the pledge make the date (2026-09-11)

**Context.** Owner: "continue building this app out. make it extremely user friendly and insightful towards goals." Explorer map: the /goals card answered one question ("how many months at this pledge?" + FI delay) and never the two a saver asks - "how far along am I?" and "will I make my date?"; no % funded anywhere, no on-track/off-track against `targetDate`, editing a date never re-solved the monthly, Home was silent about goals. Both engines needed already existed: `goalFundingMonths` (the flat timeline) and `solveSavingsGoalByDate` (Ask's inverse planner).
**Decision.** New pure engine `src/lib/engine/goals/progress.ts` - `goalProgress()`: `remainingCents`, `fundedBps` (FLOORED and clamped 0..10000 so 99.99% never reads 100%), `monthsToFunded` via `goalFundingMonths`, `fundedByDate` via `addMonthsClamped`, and for a dated goal `targetMonths` + `requiredMonthlyCents` read from `solveSavingsGoalByDate` itself (safeToSpend not consulted), so the card's "$375/mo gets you there on time" and Ask's answer for the same goal are ONE figure. Pace = funded | date-passed | no-pledge | no-date | on-track | behind, with `monthsDelta` and `gapMonthlyCents`. **The deadline is month-granular:** the form stores a month pick as YYYY-MM-01, Ask resolves "by June 2027" to the month's END, every card prints "by Jun 2027" - so pace is judged against `monthWindow(monthKey(targetDate)).to`. Against the stored 1st, a form-set "Jun 2027" at $500/mo toward $6,000 (funded 2027-06-10) read "behind by 1 month" while the identical Ask-saved goal read on pace; GP-L pins all three days of June alike. Not a data migration: the column's meaning is unchanged, the consumer reads it at the display's granularity. Copy in `progress-copy.ts`: one sentence per pace (second person, no shame, the flat-pledge assumption named where a projection is made) + `goalsHeadline` for a set. UI: `GoalProgressBlock` (bar with role=progressbar + "N% funded" + pace badge; the bar is one color in every pace - the verdict is TEXT, shape-not-color) and `GoalPaceLine` on every savings card on /goals above the FI line; the debt-free cards untouched. Home gains `GoalsProgressCard` (`src/server/goals.ts` `getGoalProgressRows`: `kind: null` only, sorted by `GOAL_PACE_ATTENTION_RANK` then name; top 3 + "All goals (N more)"; renders null with no goals) on the same `coach.today` as /goals. No writers added; demo unchanged. Named next: Ask answering "am I on track for <goal>?" against stored rows; a behind-pace nudge kind; seeded demo goals.
**Locked.** `tests/unit/goal-progress.test.ts` (GP-A..GP-L hand-derived anchors in `tests/edge-cases/goal-progress-and-pace-decisions-737.md`; solver-consistency + minimality property over a grid: exactly requiredMonthly is on-track, one cent less is behind with gap 1c; copy per pace; headline; rank order). `tests/e2e/goal-progress.spec.ts` (throwaway user; no-date -> on-track -> 25% + 3 months ahead -> behind with "$375.00/mo gets you there on time - $75.00/mo more"; Home headline + row + link).
**Critic (fresh context): cycle 1 FAIL 1 P1 - fixed same-session.** P1-1: the verdict leaned on `savedCents`, a hand-typed field with no unset state (Ask-saved goals start at $0), and named only the pledge as its assumption: probed one month after an Ask save with saved never updated, the row read "Behind pace ... $545.46/mo" on Home at rank 0 with zero reader action - a coaching judgment whose basis was invisible (lesson: an answer is only as believable as its visible inputs; a zero is a claim). Fix: every projecting sentence now says "counting the $X you've marked saved", the behind sentence offers "update what you've saved and this recalculates" before the bigger pledge, and the Home row prints "$X marked saved of $Y" beside the percent (GP-M anchor + an every-projection-names-both-inputs lock). P2s fixed: "is here" -> "has passed" for an older target month; "1 of 3 goals need" -> "needs"; "you'll be funded" -> "has this funded"; Home name gets `title` and the badge wraps under it; the one tautological grid assertion replaced with an independent oracle. P2s accepted and named: `wholeMonthsUntil` caps at 1200 months so a >100-year date overstates the required monthly (the month input has no max); a regex-passing invalid stored date would split the two readers (unreachable through current writers).

## #738 - Ask answers on-track for a stored savings goal (2026-09-11)

**Context.** GL.1 (#737) put progress + pace on every savings card and on Home. Ask still only inverse-planned a NEW amount + date (`savings_goal_by_date`); a reader with three named goals could not ask about any of them.
**Decision.** New intent `goal_status` `{ nameQuery }`. Parser `goalStatusFromQuestion` (shared with `intentFromKind`) requires pace/status vocabulary and an extractable name, then commits only when `matchGoalName` against the reader's stored savings names is unique or ambiguous (`none` declines so later routes and the unknown/LLM path still run). Amount-bearing questions stay the inverse planner / wealth target; retirement/FI/debt-free and payoff/paydown/snowball words decline. Timeframe / unreadable date / `at <store>` is `unknown` only after a unique match, and only on the leftover tokens *outside* the stored name (`leftoverAfterGoalName`) — a goal named "June wedding" is askable; "Japan trip this month" still abstains. A nameless "am I on track for my savings goal?" is `unknown` — never the only or first goal. Matching is exact normalized, then unique whole-word containment; reverse containment only when leftover tokens are filler (`my` / `goal` / `fund`); "car" ≠ "card"; a 1-token stored name never reverse-matches; ambiguous and none are first-class. Savings rows only (`getGoalProgressRows` / `listSavingsGoalNames`, both `userId` + `kind: null`). Answer `detail` is byte-identical to `goalPaceSentence`; headline is `{stored name} — {GOAL_PACE_LABEL}`. No-match and ambiguous answers carry no figures. Spend synonyms inside a goal name ("trip", "vacation") are the goal, not a Travel-group total — `resolveSpendTarget` is not consulted. Frame does not swap names this slice. Demo read-only, no writers. No new money math: every figure is `goalProgress` (#737 / §Goal-progress-and-pace).
**Locked.** `tests/unit/goal-name-match.test.ts` (unique / none / ambiguous / prefix-not-whole-word / 1-token reverse / filler-only reverse / leftoverAfterGoalName). `tests/unit/assistant-goal-status.test.ts` (routing + abstention majority + stolen-route pins + dated-name goals + `intentFromKind` re-derives the name + detail === `goalPaceSentence` on GP-A). `tests/e2e/goal-status-ask.spec.ts` (throwaway user; card sentence === Ask answer).
**Critic (fresh context): cycles 1–4 FAIL, all blocking findings fixed same-session.** Cycle 1: 1 P0 + 3 P1 — mid-parser `unknown` deleted `debt_payoff` ("on track to pay off my car loan"); bare behind/progress claimed rent/bills; blocked leftover `"spending"` returned unknown instead of `null` (stole `spend_total`); 1-token reverse containment (`Fund` inside "emergency fund"). Cycle 2: 2 P0 + 3 P1 — noun spellings (`payoff`/`snowball`) still stole `debt_payoff`; reverse containment of a 2-token name inside "car loan payoff" printed wrong-goal dollars; `income` / `account_balance` / `safe_to_spend` / `cash_needed` lost questions they answered at HEAD; unmatched nouns claimed a no-match and hid the miner. Fix: commit `goal_status` only when `matchGoalName` is unique/ambiguous; server passes `listSavingsGoalNames` into the parser. Cycle 3: 1 P0 — timeframe/`at` unknown ran *before* match, so "spending last month" extracted a fake name and deleted 67 later routes. Cycle 4: 1 P1 — after unique match, timeframe still ran on the *whole question*, so a goal named "June wedding" / "Summer 2027 trip" / "Trip at sea" was identified then discarded. Fix: leftover-token window. No 5th critic (budget 4); residual P2s accepted: a stored name that is also an app concept (`Spending plan`) outranks that standing route; a single generic token (`fund`) can uniquely hit a multi-word goal (headline prints the stored name); `fundedPercent` is duplicated at the Ask boundary; `listSavingsGoalNames` runs on every Ask; two rows with the same normalized name produce a dead-end disambiguation; some natural phrasings (`am I behind on my Japan trip?`) stay unknown; demo has no seeded goals (GL.4).

## #739 - The goals wave closes: behind-pace nudge, seeded demo goals, the 1200-month horizon (2026-09-11)

**Context.** GL.1 (#737) shipped progress + pace; GL.2 (#738) shipped Ask against stored rows. Three dead ends remained open in TASKS Wave GL: the Today feed did not know a slipping goal existed (GL.3), the live demo /goals was the empty worked example (GL.4), and `wholeMonthsUntil` saturates at its 1200-month cap so a >100-year target date was planned against the cap while the card printed the reader's own far figure (GL.5, #737 critic P2).

**Decision.**
- **GL.5** — the horizon is a WRITER's rule, one predicate beside the cap: `isBeyondPlanningHorizon(today, target)` in `src/lib/engine/solve/debt-free-by-date.ts` (the target month's END — GP-L — vs today + 1201 months; the month-END basis because the form stores the 1st while every deadline judges the month's end), called by `updateGoalTargetDate` (inline field error naming the horizon month) AND both Ask save writers (`saveSavingsGoal`, `saveDebtFreeGoal` — the critic's P1-3: the savings solver only unreachables a PAST date, so a 2200 target would have persisted a plan computed at the saturated 1200 months). The month input carries a native `max` (viewer's local clock — advisory; the server's refusal wins, named in code) and the ceiling is disclosed in an always-describedby'd hint. `createGoal` takes no date — nothing to guard.
- **GL.4** — the demo seed carries two savings goals, byte-shape identical to `createGoal`'s rows (`kind: null`): Vacation Fund $2,400 / $800 / $200/mo, no date (no-date pace, funded Feb 2027, 33% floored) and New Car Fund $6,000 / $600 / $150/mo, Jun 2027 (BEHIND by 24 months: 36 to fund vs 12 to the month-END; required $450/mo, gap $300/mo). Dates derive from `--asOf`; names avoid every e2e-created demo goal and Ask-spec noun. Seed log counts goals.
- **GL.3** — new nudge kind `goal_behind_pace` (ACTION tier, dismissable, never pushed). Rows come from the caller's own `goalProgress` rows via `goalPaceNudgeRowsFrom` (only `isGoalPaceNudgeWorthy` paces: behind | date-passed) — the feed re-derives NOTHING about pace, so it cannot disagree with the card about who is slipping. `centsAtStake` is `gapMonthlyCents` verbatim (the EXTRA monthly needed, never the pledge; 0 for a passed date); `sortDate` is the target month's END (the deadline the verdict was judged on); the dismissal fact is `goal_behind_pace:<goalId>:<YYYY-MM>` — a moved date returns the row, an unchanged one stays gone. The detail line is the goal card's own `goalPaceSentence` rendered from a verbatim context group (`Proposal.goalNudge`) — one copy truth with /goals and Home (the GL.2 invariant). Title branches on pace (`is behind pace` | `'s date has passed`, the card badges' wording); the why-line names the fact on a passed date instead of printing a $0 remedy. Engagement closed set gains `nudge:goal_behind_pace`; demo dismissal stays session-only (existing fence).

**E2e ripples GL.4 caused (fixed same-session, critic P1-1).** The demo's planned-savings line is now GOAL-DERIVED $350.00: glass-box's L.29 which-zero lock moved to a throwaway fixture where unset-$0 binds by construction (inline income seeding, the conscious-buckets idiom); the demo sections pin "Planned savings (goals)" / $350.00 / no control; the demo guilt-free panel keeps its penny-match and loses the "nothing is invented" provenance clause (a reader-chosen figure now enters the identity — `trace.ts dataDerived`). Also honest: conscious-buckets' `legendCents['conscious-savings'] === 350_00`, and the budgets composition card keeps "not set" (savingsTargetBps stays null; goals are larger but the note only says so when a target exists).

**Locked.** `tests/unit/goal-date-horizon.test.ts` (writer refusals: updateGoalTargetDate Jul-2126 refused / Jun-2126 accepted / 2027-06 stored as the 1st; BOTH Ask saves refuse 2200-01-01 with nothing persisted; form carries `max` + the ceiling disclosure). `tests/unit/seed-goals.test.ts` (two kind-null goals; names avoid e2e-created ones; Vacation 8-months/33%-floored; New Car behind-24/gap-300; the card sentence from seeded fields). `tests/unit/goal-pace-nudge.test.ts` (engine: ACTION tier, verbatim gap/0, dismissal fact keys goal+month, sortDate = month END, dated-ACTION ordering; copy: byte-identical detail, both titles, both why-lines). `tests/e2e/goal-demo-and-nudge.spec.ts` (demo Home "1 of 2 goals needs a look" + behind-first row; /goals both cards with badges/percent/sentence; dashboard `nudge-goal_behind_pace` with the card sentence; throwaway user: 2126-08 server-refused inline, 3200-01 blocked client-side, 2027-06 saves, cleanup delete). Demo e2e ripples re-locked in glass-box.spec.ts + conscious-buckets.spec.ts.

**Critic (fresh context): cycle 1 FAIL 3 P1 — all fixed same-session; cycle 2 PASS (0 P0, 0 P1).** Cycle-1 P1s: demo plan e2e pinned the pre-seed $0 savings world; date-passed row titled "behind pace" with a "$0/mo more needed" why-line; Ask save writers could persist past-horizon dates. Residual P2s accepted: the client `max` uses the viewer's local clock while the server judges `businessToday` (they agree for a real signed-in user — the only writer; demo fenced; server wins), and the glass-box comment now correctly credits conscious-buckets for the demo $350 lock.
